# JIANMO — Character Model Viewer

Online preview: https://gsvegetable.github.io/jianmo/

JIANMO is a browser-based 3D character collection built with React Three Fiber and Three.js. It currently contains four *Bocchi the Rock!* character assets and a layered acrylic-style charm.

## Release

- Current version: 0.10.0
- Runtime formats: glTF 2.0 / GLB and VRM
- VRM support: MToon materials and spring-bone updates through `@pixiv/three-vrm`
- Current character fallback assets: procedural GLBs in `public/models/characters/`
- Charm: layered GLB in `public/models/charms/`

## Important asset status

The four character GLBs currently in the repository were generated by the legacy procedural SDF pipeline. They have dense meshes, but dense topology does not make a character a high-quality sculpt. The current assets should be treated as placeholders, not as finished collectible-grade sculpts.

The repository does not currently contain the four VRM files mentioned in the optional VRM workflow. The viewer tries a VRM first when one is supplied, then falls back to the matching GLB. A missing VRM is therefore expected and does not prevent the existing GLB from loading.

## Viewer behavior

- Responsive layout for desktop and tablet-sized screens
- Character and charm collections
- Orbit rotation, zoom and controlled camera framing
- Consistent model scale and grounded placement
- Studio-style key, fill and rim lighting
- Explicit loading and missing-asset states
- Vite base-path-aware asset URLs for GitHub Pages

## Authoring and source assets

The legacy procedural generator is retained for reproducibility and comparison:

```bash
python3 tools/build_characters.py
python3 tools/build_characters.py --only kita --spacing 0.006
```

Its implementation is in `tools/chibi/`. It is not the recommended route for the next generation of hero character models.

For future production-grade character replacements, preserve an editable authoring source alongside each runtime export. The preferred handoff is a Blender `.blend` source plus exported GLB; FBX and OBJ may be included where they preserve the required geometry and materials. A GLB alone is a delivery format, not a substitute for the editable source project.

The optional VRM route is supported for rigged, animatable characters. VRM files can be placed in `public/models/characters/` with the same basename as the corresponding GLB and a `.vrm` extension.

## The chibi charm

The charm is built from a layered illustration rather than from the SDF character generator. Its source pipeline lives in `tools/charm/`:

1. Trace and segment the source illustration.
2. Compose the front and back artwork.
3. Convert the outlines into closed 2D meshes.
4. Give the layers depth and export a GLB.

Build it with:

```bash
python3 tools/charm/build_charm.py --out build/charm
```

The source character sheet is supplied through the `CHARM_SHEET` environment variable.

## Deployment

Every push to `main` triggers GitHub Actions and deploys the production build to GitHub Pages. Keep the version in `README.md`, `package.json` and the root package entry in `package-lock.json` aligned.
